# Yessr!

**옛썰!** 현재 요청의 요약과 지정한 출력 형식을 안내하고, 검사 가능한 위반에 수정을 요청하는 로컬 Codex·Claude Code용 플러그인입니다.

현재는 **0.1.0 실험용 구현**입니다. 응답 정책과 검사 제어기는 두 호스트가 공유합니다. 초기 호환 후보는 Claude Code `2.1.251`에서 세션 한정 로딩과 정책 주입·요청 판별을 확인했습니다. 실제 모델 응답과 Stop 연결은 사용 가능한 테스트 계정이 없어 검증하지 못했습니다. 기존 Codex v1의 검증 범위는 아래에 구분하여 기록했습니다. [설치와 신뢰 검토](plugins/yessr/README.md#설치와-신뢰-검토)를 먼저 읽으십시오.

Claude Code에서 저장소 루트 기준으로 현재 세션에만 불러오려면 다음 명령을 사용하십시오. Node.js 24가 필요합니다.

```sh
claude --plugin-dir ./plugins/yessr
```

Claude 웹·일반 채팅 앱이나 다른 에이전트 호스트는 지원 범위에 포함하지 않습니다.

## v1 목표

- 일반 진행 보고·질문·최종 답변은 현재 요청을 짧게 복명복창합니다. 명시적으로 생략을 요청하면 복명복창하지 않습니다.
- JSON·코드·고정 문자열 등 정확한 출력 요청에는 복명복창이나 마무리 설명을 붙이지 않습니다.
- 한국어를 유지하면서 ASD-STE100의 명료한 작성 원칙을 참고합니다. 코드·식별자·인용·조건·예외·불확실성을 보존합니다.
- 일반 자연어의 출력 요구를 보수적으로 판별합니다. 요구가 불명확하거나 상충하면 자동 수정을 요청하지 않습니다.
- 검사 가능한 위반에만 플러그인 제어기 기준으로 요청당 한 번 이하의 수정을 요청합니다. 응답 규칙의 정본은 하나만 유지합니다.

## 설계 범위와 한계

실제 상위 지침과 명시적인 출력 요청을 우선합니다. 복명복창 접두, 원시 응답 전체의 JSON 문법, 고정 문자열 일치를 검사합니다. 한국어 문체는 차단 조건으로 사용하지 않습니다. 인용·상충·조건·이전 형식이 불명확하면 자동 수정을 생략합니다.

접두 검사는 요약의 정확성을 보장하지 않습니다. 한국어 작성 원칙의 적용을 정식 ASD-STE100 준수나 인증으로 표현하지 않습니다.

Stop 후크의 수정 요청은 추가 응답을 유도합니다. 이미 표시된 답변을 회수하거나 모든 진행 보고를 표시 전에 차단하지 않습니다. 수정 횟수 제한은 이 플러그인의 요청에만 적용하며, 다른 플러그인의 동작까지 통제하지 않습니다.

응답 지침의 정본은 [plugins/yessr/policy.json](plugins/yessr/policy.json)입니다. 지원 예문, 이전 형식의 보수적 처리, 정상 설치·신뢰 절차와 검증 한계는 [플러그인 README](plugins/yessr/README.md)에 있습니다.

## 로컬 검증

Node.js 24에서 저장소 루트 기준으로 실행합니다. 추가 패키지 설치나 빌드 단계는 없습니다.

```sh
node --test tests/yessr.test.mjs
claude plugin validate --strict ./plugins/yessr
claude plugin validate --strict .
```

단위·프로세스 시험 165개와 Claude 패키지·marketplace의 엄격 검증이 통과했습니다. Claude의 요청 식별자와 환경변수, 정상·위반 출력, 중복·동시 Stop, 재개·압축 입력을 검사합니다. 합성 입력 시험은 실제 모델 응답의 검증을 대신하지 않습니다.

## 기존 Codex v1 검증

범용화 이전 v1은 Node.js `24.15.0`과 Codex CLI `0.164.0-alpha.11.1`에서 정상 설치·신뢰와 세 후크의 실제 호출을 확인했습니다. 별도 실제 CLI 시험에서는 형식 시나리오 8개의 최종 응답 중 7개가 통과했습니다. 요청 요약 누락과 개행 문자열 오류는 수정되었지만, `" OK "`의 뒤 공백은 한 번의 수정 요청 후에도 누락되었습니다. 실제 결과는 `" OK"`였습니다.

명시 UUID 재개, 지속 JSON 요청과 형식 해제, 목표 변경, 실제 `/compact`, 압축 후 첫 진행 보고와 최종 답변의 요청 요약을 확인했습니다. 실제 후크 입력의 `SessionStart.source`와 `Stop.stop_hook_active`도 기록했습니다. 기존 전역 규칙이 함께 적용되어 응답 전체를 Yessr만의 효과로 해석할 수는 없습니다. Desktop 직접 입력·압축과 다른 플러그인의 Stop 동시 실행은 미검증입니다. 범용화 후보의 Codex 실제 모델 시험은 다시 실행하지 않았습니다. 자세한 범위는 [실제 검증과 남은 한계](plugins/yessr/README.md#실제-검증과-남은-한계)에 있습니다.
