# Yessr!

**옛썰!** 현재 요청을 짧게 요약하고, 지정한 출력 형식을 지키도록 돕는 **로컬 Codex·Claude Code용 응답 규칙 플러그인**입니다.

여러 대화를 오갈 때 답변 첫 줄에서 현재 목표를 파악할 수 있도록 합니다. JSON·코드·고정 문자열만 요청하면 요약과 부연 설명을 생략하도록 안내합니다. 검사 가능한 위반에는 같은 요청에서 최대 한 번의 수정을 요청합니다. 응답 정책과 검사 제어기는 두 호스트가 공유합니다.

> **상태: 0.1.0 실험용 구현**
>
> 초기 공용 후보는 Claude Code `2.1.251`에서 세션 한정 로딩·정책 주입·요청 판별을 확인했습니다. 실제 모델 응답과 Stop 연결은 미검증입니다. 범용화 이전 Codex v1은 Node.js `24.15.0`과 CLI `0.164.0-alpha.11.1`에서 설치·후크 신뢰·실제 호출을 확인했습니다. 현재 공용 구현의 검증과 기존 Codex v1 기록은 아래에서 구분합니다. 수정 후에도 출력 형식이 틀릴 수 있습니다.

## 빠른 시작

Codex는 아래 설치 절차를, Claude Code는 [Claude 사용자 안내](#claude-사용자-안내)를 따르십시오.

### 준비 사항

- 이 저장소를 로컬에 준비하십시오. 아래 셸 명령은 저장소 루트에서 실행합니다.
- 호스트 실행 환경의 `PATH`에 Node.js 24가 있어야 합니다. npm 패키지 설치나 빌드는 필요하지 않습니다.
- Codex 또는 Claude Code의 로컬 플러그인 실행 환경이 필요합니다. 최소 지원 버전 전체와 다른 운영체제의 호환성은 확인하지 않았습니다.

버전을 먼저 확인하십시오.

```sh
node --version
codex --version
```

### Codex 설치와 활성화

1. 로컬 marketplace를 등록하십시오.

   ```sh
   codex plugin marketplace add .
   ```

2. Codex Desktop의 Plugins Directory에서 **Yessr 로컬 검증 → Yessr!**를 선택하여 설치하십시오.
3. 사용할 프로젝트에서 플러그인을 활성화하십시오.
4. 같은 환경의 Codex CLI에서 `/hooks`를 열고 Yessr의 `SessionStart`, `UserPromptSubmit`, `Stop` 정의와 명령을 검토한 뒤 신뢰하십시오.
5. 새 세션에서 아래 사용 예시로 응답을 확인하십시오.

**설치·활성화와 후크 신뢰는 별개입니다.** 신뢰하지 않은 후크는 실행되지 않습니다. 후크 정의가 바뀌면 다시 검토해야 합니다. 절차의 근거는 공식 [플러그인 설치 문서](https://developers.openai.com/plugins/build/plugins)와 [후크 신뢰 문서](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)입니다.

이전 `0.1.0` 후보가 설치되어 있다면 [설치 사본 확인과 재설치 안내](plugins/yessr/README.md#설치와-신뢰-검토)를 따르십시오. 버전 표시만으로 같은 내용인지 판단할 수 없습니다.

## Claude 사용자 안내

Claude Code도 같은 [policy.json](plugins/yessr/policy.json)과 후크 제어기를 사용합니다. 저장소 루트에서 Node.js 버전과 Claude Code 버전을 먼저 확인하십시오.

```sh
node --version
claude --version
```

### 현재 세션에서 사용하기

```sh
claude --plugin-dir ./plugins/yessr
```

`--plugin-dir`는 현재 세션에만 플러그인을 불러옵니다. 이미 설치한 Yessr를 불러오는 세션에는 이 옵션을 추가하여 중복 로드하지 마십시오. CLI 옵션의 근거는 공식 [Claude Code 플러그인 개발 문서](https://code.claude.com/docs/en/plugins/create#load-a-plugin-for-one-session)입니다.

### 계속 사용하기

1. 로컬 marketplace를 등록하십시오.

   ```sh
   claude plugin marketplace add .
   ```

2. Yessr를 설치하십시오.

   ```sh
   claude plugin install yessr@yessr-local
   ```

3. 새 Claude Code 세션을 시작하십시오.
4. `/hooks`에서 `SessionStart`, `UserPromptSubmit`, `Stop`과 실행 명령을 검토하십시오.
5. `캐시 정책을 설명해줘.`와 `정확히 "OK"만 출력해줘.`로 일반 설명과 정확 출력 예외를 각각 확인하십시오.

설치 명령의 근거는 공식 [Claude Code marketplace 문서](https://code.claude.com/docs/en/plugin-marketplaces)입니다. 현재 제어기는 Claude Code의 `prompt_id`와 `CLAUDE_PLUGIN_DATA`를 사용합니다. 이 값을 제공하지 않는 버전에서는 자동 검사가 생략될 수 있습니다. Claude Code `2.1.251`에서 확인한 로딩·정책 주입·요청 판별 기록과 실제 모델·Stop 미검증 범위는 [상세 검증 기록](plugins/yessr/README.md#실제-검증과-남은-한계)에 있습니다.

Claude 웹·일반 채팅 앱과 다른 에이전트 호스트는 이 플러그인의 지원 대상이 아닙니다. 기존 `CLAUDE.md`를 교체하거나 정책 본문을 별도로 복제할 필요는 없습니다.

## 사용 예시

플러그인을 불러온 세션에서 전용 명령 없이 평소처럼 요청합니다. 아래 출력은 **기대 형식을 설명하는 예시**이며 실제 모델 응답을 보장하지 않습니다. 두 호스트는 같은 검사 로직을 사용하지만, 실제 응답 연결을 검증한 범위는 서로 다릅니다.

### 일반 설명

새 세션에서 `캐시 정책을 설명해줘.`라고 요청하면 다음처럼 현재 요청 요약으로 시작하도록 안내합니다.

```text
**요청 요약:** 캐시 정책에 대한 설명을 요청하셨습니다.
캐시 정책은 저장할 데이터와 보관 기간을 정합니다.
```

일반 진행 보고·질문·최종 답변에 같은 작성 원칙을 적용하도록 안내합니다. 한국어는 하십시오체로 작성하고, 한 문장에 한 가지 요점을 담도록 합니다. 코드·식별자·인용·조건·예외·불확실성은 보존합니다.

### 출력 형식 지정과 해제

| 요청 예시 | 기대 동작 |
| --- | --- |
| `결과를 JSON으로 반환해줘.` | 요청 요약과 코드 펜스 없이 JSON만 출력 |
| `코드만 출력해줘.` | 요청 요약과 부연 설명 없이 코드만 출력하도록 안내 |
| `정확히 "OK"만 출력해줘.` | 따옴표를 제외한 `OK`와 완전히 같은 응답 검사 |
| `요청 요약은 생략하고 캐시를 설명해줘.` | 요청 요약 생략을 안내하고 접두 교정은 생략 |
| `이전 출력 형식 제한을 해제하고 일반 설명으로 답해줘.` | 이전 형식 제한을 해제하고 일반 설명 검사로 전환 |

고정 문자열은 JSON 문자열 표기의 큰따옴표(`"`)를 사용합니다. 예를 들어 `정확히 "A\nB"만 출력해줘.`의 기대값은 실제 개행을 포함한 두 줄입니다. 공백·개행·Unicode를 trim하거나 정규화하지 않습니다.

한 번이라도 정확 출력 요청을 한 뒤에는 일반 설명 검사를 보류할 수 있습니다. 이전 제약을 실수로 덮어쓰지 않기 위한 처리입니다. 일반 설명으로 돌아가려면 표의 **명시적 형식 해제 문장**을 사용하십시오. 세부 조건과 영문 예시는 [인식 예문](plugins/yessr/README.md#인식-예문)과 [이전 형식의 영향](plugins/yessr/README.md#이전-형식의-영향)에 있습니다.

## 검사 범위

정책 안내와 자동 검사는 범위가 다릅니다. 정책은 응답 작성을 안내하고, `Stop` 검사는 호스트가 제공한 최신 최종 응답의 구조를 확인합니다.

| 대상 | 자동 검사 | 검사하지 않는 내용 |
| --- | --- | --- |
| 일반 설명 (`prose`) | `**요청 요약:**`으로 시작하고 같은 줄에 요약 내용이 있는지 | 요약의 정확성, 모든 진행 보고·질문의 준수 여부 |
| JSON (`json`) | 원시 응답 전체를 `JSON.parse`로 읽을 수 있는지 | 스키마, 필드, 자료형 등 요청 의미의 충족 여부 |
| 고정 문자열 (`literal`) | 기대 문자열과 완전히 같은지 | 문자열 내용의 사실성 |
| 코드 (`code`) | 없음. 정책으로만 안내 | 언어 판별, 실행 결과, 자연어 혼입 여부 |
| 불명확한 요청 (`unknown`) | 없음. 수정 요청 생략 | 미지원 형식과 해석이 불명확한 조건 |

JSON은 객체·배열뿐 아니라 문자열·숫자·불리언·`null`도 허용합니다. 인용·부정·조건·상충하는 출력 요구·이전 제약이 불명확하면 자동 수정을 생략합니다. 한국어 문체와 요약 충실도는 차단 조건으로 사용하지 않으며, ASD-STE100 준수나 인증을 뜻하지 않습니다.

`Stop`의 수정 요청은 **추가 응답을 유도**합니다. 이미 표시된 답변을 회수하거나 모든 메시지를 표시 전에 차단하지 않습니다. 같은 요청에 대한 수정 요청은 이 플러그인의 제어기 기준 최대 한 번이며, 다른 플러그인의 요청 횟수까지 통제하지 않습니다. 실제 상위 지침과 명시적인 출력 요청이 우선합니다.

## 동작 흐름과 로컬 데이터

| 후크 | 역할 |
| --- | --- |
| `SessionStart` | [policy.json](plugins/yessr/policy.json)의 응답 작성 원칙 주입 |
| `UserPromptSubmit` | 현재 요청의 출력 조건을 판별하고 세션·턴 상태 저장 |
| `Stop` | 최신 최종 응답 검사 후, 조건이 충족되면 한 번의 수정 요청 |

각 후크는 같은 [제어기](plugins/yessr/hooks/response.mjs)를 호출합니다. 응답 지침의 정본은 `policy.json` 하나이며, README는 사용법과 한계를 설명합니다. 플러그인은 기존 전역 지침·설정·신뢰 정보를 직접 수정하지 않습니다.

상태는 호스트가 제공한 데이터 폴더 아래 `state/<세션 ID 해시>/`에 저장합니다. Codex는 `PLUGIN_DATA`, Claude Code는 `CLAUDE_PLUGIN_DATA`를 사용하며 정상 호스트 환경에서는 서로 다른 폴더를 사용합니다. 정상 실행에는 해당 경로의 쓰기 권한이 필요합니다.

- `session.json`: 출력 조건, 요청 해시, 수정 요청 사용 여부를 저장합니다. **고정 문자열 비교에 필요한 기대값이 포함될 수 있습니다.**
- `receipts.jsonl`: 세션·턴 식별자의 해시, 후크 이벤트, 판별 결과, 수정 요청 준비 여부를 기록합니다. 요청·응답 본문은 기록하지 않습니다.

후크 제어기는 외부 네트워크 요청을 하지 않습니다. 이는 플러그인 자체의 범위이며 호스트의 데이터 처리 방식까지 설명하지는 않습니다. 상태 유실·손상·저장 실패나 호스트 식별자 불일치가 있으면 수정 요청을 생략합니다. 상태 파일 삭제를 형식 제한 해제 방법으로 사용하지 마십시오.

## 문제 해결

| 증상 | 확인할 항목과 조치 |
| --- | --- |
| 설치했지만 후크가 실행되지 않음 | 해당 호스트의 `/hooks`에서 세 이벤트와 실행 명령을 확인하십시오. Codex는 프로젝트 활성화와 후크 신뢰 상태도 확인하십시오. `node`가 호스트 환경의 `PATH`에 있어야 합니다. |
| 수정한 소스가 설치본에 반영되지 않음 | 설치 사본과 저장소 소스를 구분하십시오. 같은 `0.1.0`도 내용이 다를 수 있으므로 [재설치 안내](plugins/yessr/README.md#설치와-신뢰-검토)에 따라 manifest와 후크를 확인하십시오. |
| 정확 출력 요청 뒤에 요약 누락을 교정하지 않음 | 이전 형식 제한 때문에 검사를 보류할 수 있습니다. `이전 출력 형식 제한을 해제하고 일반 설명으로 답해줘.`를 사용하십시오. |
| 특정 표현이나 코드 응답을 교정하지 않음 | `unknown`과 `code`는 자동 교정하지 않습니다. [지원 예문](plugins/yessr/README.md#인식-예문)과 비교하십시오. |
| 수정 후에도 형식이 틀림 | 같은 요청의 수정 요청 상한은 한 번입니다. 최종 출력은 별도로 확인하십시오. 기존 Codex v1의 실제 시험에서도 뒤 공백 누락이 남았습니다. |

후크가 호출되는데도 예상과 다르면 `receipts.jsonl`의 `event`, `mode`, `code`, `blockPrepared`와 상태 경로의 쓰기 권한을 확인하십시오. `blockPrepared: true`는 수정 요청을 준비했다는 기록이며 최종 응답의 성공을 뜻하지 않습니다. 상태 파일을 공유할 때는 고정 문자열 기대값 등 민감한 내용을 먼저 제거하십시오.

## 개발과 검증

### 저장소 구성

```text
.agents/plugins/marketplace.json       로컬 marketplace 목록
.claude-plugin/marketplace.json       Claude Code marketplace 목록
plugins/yessr/
├── .codex-plugin/plugin.json          플러그인 정보와 후크 경로
├── .claude-plugin/plugin.json         Claude Code 플러그인 정보
├── hooks/hooks.json                  세 후크의 등록 정보
├── hooks/response.mjs                판별·상태 관리·응답 검사
├── policy.json                       응답 지침의 정본
├── README.md                         상세 규칙·호환성·검증 한계
└── THIRD-PARTY-NOTICES.md             차용한 문구의 출처
tests/yessr.test.mjs                   단위·프로세스 시험
```

Codex는 `.codex-plugin/plugin.json`을 사용하는 legacy manifest 형식입니다. 검증한 CLI의 로딩 경로를 유지하기 위해 루트 `plugin.json`을 함께 두지 않습니다. Claude Code는 `.claude-plugin/plugin.json`을 사용하고 기본 `hooks/hooks.json`을 발견합니다. 두 manifest는 같은 정책과 제어기를 연결합니다. 호스트별 근거는 [설치와 신뢰 검토](plugins/yessr/README.md#설치와-신뢰-검토)에 있습니다.

### 로컬 시험

Node.js 24에서 저장소 루트 기준으로 실행하십시오.

```sh
node --test tests/yessr.test.mjs
claude plugin validate --strict ./plugins/yessr
claude plugin validate --strict .
```

시험은 두 호스트의 요청 식별자와 데이터 폴더, 요청 판별, 형식 위반의 통과·실패 조건, 세션 격리, 한 번의 수정 요청 상한, 상태 손상·쓰기 실패, UTF-8 입력과 실제 자식 프로세스의 stdin/stdout을 확인합니다. Claude의 두 검증 명령은 패키지와 marketplace 형식을 검사합니다. 합성 후크 입력과 패키지 검증만으로 실제 모델 응답이나 Desktop 동작을 검증할 수는 없습니다.

### 기존 Codex v1 실제 검증 기록

다음은 범용화 이전 Codex v1의 기록입니다. 현재 공용 구현의 Codex 실제 모델 시험은 다시 실행하지 않았습니다.

- **형식 시나리오:** 8개 최종 응답 중 7개 통과. 요청 요약 누락과 개행 문자열 오류는 수정되었지만, `" OK "`는 한 번의 수정 후에도 뒤 공백이 빠진 `" OK"`로 남았습니다.
- **재개·압축:** 명시 UUID 재개, 지속 JSON 요청과 형식 해제, 목표 변경, 실제 `/compact`, 압축 후 첫 진행 보고와 최종 답변의 요청 요약을 확인했습니다. 실제 입력의 `SessionStart.source`와 `Stop.stop_hook_active`도 기록했습니다.
- **검증 한계:** 기존 전역 규칙이 함께 적용되었으므로 응답 전체를 Yessr만의 효과로 해석할 수 없습니다. Desktop 직접 입력·압축과 다른 플러그인의 Stop 동시 실행은 미검증입니다.

위 내용은 기존 시험의 기록이며, 호스트 업데이트 후의 동작 보장이 아닙니다. 상세 환경과 실패 사례는 [실제 검증과 남은 한계](plugins/yessr/README.md#실제-검증과-남은-한계)에 있습니다.
